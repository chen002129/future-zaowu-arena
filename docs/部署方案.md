# 部署方案 · 小程序先上线，再关联公众号

> 状态：v1.4 · 2026-10-07  
> 决策依据：路径为「**先上线小程序 → 再关联公众号**」。这份文档把每一步的依据、卡点、替代路径写清楚。  
> 最新变更：§5.4 —— 小程序 → 公众号 / 视频号的入口已核实并写进代码（已落地 `miniprogram/config.js`）。  
> ⚠️ 关于账号体系：**产品已确定零账号**（不做登录、不接云服务）。§十、§十一、§十二 为登录方案的**历史参考**，保留以备将来重启，当前工程内不含任何登录代码。

## 一、总体路径（三段式）

```
阶段 ①  小程序先跑起来          不依赖公众号，独立可上线
        ├─ 注册小程序账号（主体决定能力上限）
        ├─ 选服务类目（决定能否过审）
        ├─ 开通微信云开发（后端零运维）
        ├─ 接通「小程序原生登录」（登录口径定稿，见 §十二）
        └─ 开发 → 提交审核 → 发布

阶段 ②  再打通公众号              核心是「关联」，不是「部署」
        ├─ 公众号后台关联小程序（所有公众号都能做）
        ├─ 自定义菜单跳小程序（需关联；未认证号受限）
        └─ 图文插小程序卡片（**无需关联即可用**）

阶段 ③  云端自动化（持续运营）
        ├─ 定时抓取 → 审核 → 发布
        ├─ 订阅消息截止提醒
        └─ 公众号每周精选推文
```

**为什么小程序先上线是对的**：小程序的开发、审核、发布完全不依赖公众号；反过来，公众号要展示小程序，得先有个已发布的小程序。顺序不能倒。

**登录在这条顺序里的位置（2026-10-07 补）**：登录不是等公众号认证办完才有的东西——小程序一旦有 AppID + 云开发环境，`wx.login` 原生登录当场就能用。所以登录跟着**阶段①**落地，公众号关联只是给小程序多开两条入口，不参与登录链路。详见 §十二。

**认证费的省钱组合（同样 300 元，办成两件事）：**

```
推荐路径（总花费 300 元/年）：

  第 2 步  公众号后台 → 小程序管理
           → 快速注册并认证小程序      免认证费（复用资质）
  第 3 步  注册时勾选「复用微信认证资质」 ← 关键，漏勾会单独收费且不退

  结果：公众号 ✅已认证 + 小程序 ✅已认证 + 两者自动关联（阶段②直接完成）
  对比：单独认证小程序也要 300 元/年，公众号却仍是未认证
```

依据（腾讯客服官方口径）：已认证的企业类型公众号可复用资质快速注册并认证小程序，**无需重新提交主体材料、无需对公打款、免 300 元认证费**；复用资质创建的小程序**默认关联该公众号**。

### 2.1 认证能不能绕过（2026-10-07 专门核实）

**先纠正一个容易搞错的点：微信认证本身不是「发布审核」的前提。** 官方《微信小程序认证指引》原文写着：

> 账号类型为**企业**的微信应用号，完成注册后即可取得大部分的初始化开发管理能力，**认证成功不作为提交发布审核的前提**，但支付功能等腾讯有特别规定的除外。

**但卡点在后面一环——备案。** 备案才是真正的门槛：

| 环节             | 是否强制                         | 是否要求先认证                                       |
| -------------- | ---------------------------- | --------------------------------------------- |
| 提交审核（代码审核）     | 需要                           | ❌ 不要求（官方原文）                                   |
| **小程序备案（ICP）** | **✅ 强制，2023-09-01 起未备案不得上架** | **✅ 非个人主体需先完成微信认证才能发起备案**（多份实操口径一致，含微信开放社区文章） |
| 发布上架           | 需要备案通过                       | 间接要求认证                                        |

**所以准确的结论是：**

- **开发阶段能绕过去。** 代码写完可以上传到「开发版」和「体验版」，用真机扫码体验、内部试用，**全程不需要认证、不需要备案、零花费**。体验版可添加体验成员（最多 90 人左右）。→ **这是你现在就能零成本看真机的路径。**
- **正式上线绕不过去。** 想让所有人搜到、打开，必须备案；企业主体备案必须先认证。这不是技巧问题，是流程链条问题。

**三条路径对比：**

| 路径                   | 花费                      | 结果                         | 代价                                                                       |
| -------------------- | ----------------------- | -------------------------- | ------------------------------------------------------------------------ |
| **A. 企业主体 + 认证**（推荐） | 首年 300（走复用资质，覆盖公众号+小程序） | ✅ 可备案 → 可上架                | 无实质代价                                                                    |
| B. 企业主体 + 不认证        | 0                       | ⚠️ 只能停在体验版，**无法备案 → 无法上架** | 也不能改名（非个人主体改名需走认证）；无认证标识、无搜索权重                                           |
| C. 个人主体注册小程序         | 0（个人主体不在认证主体列表内，天然免认证）  | ✅ 可备案、可上架                  | ❌ **主体不可更改 = 永久锁死个人主体**；与自家企业公众号成「不同主体」，名称「未来造物赛场」可能因近似被名称审核拒；类目受限、无认证标识 |

**结论：先按 A 走，但不必现在交钱。** 开发阶段用体验版先跑真机，等你确认「这东西要正式给用户用了」，再一次性办认证。

> 补充说明（第三方口径，未在官方文档核实）：有资料称个体工商户认证优惠价为 30 元/年。若你公司名下已有或愿意办一个个体工商户执照，理论上能压低这笔钱；但那会让小程序与公众号变成**不同主体**，既无法复用资质，也失去名称上的主体一致性——**省 270 元换来一堆麻烦，不建议。**

## 三、阶段 ①：小程序上线（约 6 步）

### 3.1 注册

1. 打开 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 右上角「立即注册」→ 选**小程序**
2. 邮箱要求：**未注册过微信公众平台任何账号**的邮箱
3. 选主体类型 → 填资料 → 管理员微信扫码验证
4. 登录小程序后台 → `开发与服务 → 开发管理` 拿到 **AppID**

#### ⚠️ 别被注册页上的「微信认证」劝退（2026-10-07 用户实际卡点）

注册到最后一步「填写主体信息并选择验证方式」时，页面会摆出验证方式，**其中「微信认证」是要花钱的那一个，但它不是唯一选项，注册本身可以不花钱**：

| 主体验证方式                     | 花费            | 耗时       | 说明                                            |
| -------------------------- | ------------- | -------- | --------------------------------------------- |
| **法定代表人验证**（企业 / 个体工商户）    | **免费**        | **当场通过** | 法人本人用**绑定了本人银行卡的微信**扫码 + 人脸识别。**首选，能选就选这个**   |
| **电子营业执照验证**（企业）           | **免费**        | 很快       | 法人或办事员用「电子营业执照」小程序 / App 扫码核验主体真实性            |
| **对公账户打款验证**（仅企业，也叫「支付验证」） | **免费（且钱会退回）** | 1–2 个工作日 | 见下方详解                                         |
| 微信认证                       | **300 元/年**   | 1–5 个工作日 | 这是「认证」，不是「注册」。**注册不是必须走它**；它的作用是开通高级功能权限与认证标识 |

**「小额打款」/「支付验证」到底是什么（用户实际提问）：**

拿公司的**对公账户**，往腾讯指定的收款账户转一笔很小的钱，让腾讯确认「这个对公账户确实属于你这家公司」。规则（腾讯客服口径）：

- 金额是系统**随机生成的，精确到分**（通常不到 1 元）；填完主体信息后在验证页面能看到**腾讯的 25 位收款账号 + 本次要打的确切金额**。
- **必须在 10 天内完成打款**，逾期主体信息失效、需重新注册。
- **这笔钱不是费用，会退** —— 打款成功后 **3–10 个工作日内原路退回**对公账户。
- 填写对公账户信息时要对着《开户许可证》一字不差，收款户名必须是「腾讯公司」，金额必须分位都对。填错是最常见的卡点。
- 打款验证期间可以正常登录公众平台，超时也不会冻结账号。

> **它是最麻烦的一种**（要财务或能操作网银的人配合，填错还要重来）。所以除非法人不方便刷脸，**优先用「法定代表人验证」**，几分钟就过。

**关键区分（这是最容易混的一件事）：**

- **主体验证** = 证明「这个企业是真的」，**免费**，是注册的必经环节。
- **微信认证** = 花 300 元开通高级权限 + 拿认证标识，**是注册之外的独立动作**，可以后置。

**那 300 元什么时候真的省不掉？** 只有**正式对外上线**时（备案 + 上架那一步）。纯发体验版不涉及。

**最省的组合仍然是「复用公众号资质」**（见 §2）：公众号认证 300 元 → 公众号后台「快速注册并认证小程序」→ 小程序**免 300 元认证费**且自动关联。也就是**同样的 300 元，一次把公众号和小程序都认证掉**。  
代价是它要求公众号先完成认证（1–5 个工作日）。

**所以两条路，按你是否急着真机看效果来选：**

| 路径              | 花费                         | 多久能真机看到              | 代价                              |
| --------------- | -------------------------- | -------------------- | ------------------------------- |
| **先免费注册，后补认证**  | 现在 0，正式上线前再 300（在小程序上单独认证） | **当天**（免费验证通过即可发体验版） | 那 300 元只认证了小程序，公众号仍是未认证，自定义菜单受限 |
| **直接走复用资质**（推荐） | 300（公众号+小程序一起）             | 1–5 个工作日             | 需要等公众号认证下来                      |

### 3.2 服务类目（决定能不能过审）

| 项      | 建议                                       |
| ------ | ---------------------------------------- |
| 一级类目   | **工具 → 效率**                              |
| 二级类目   | 日程管理 / 信息查询 之类                           |
| 为什么这么选 | 避开「新闻」「资讯」类目——那类需要《互联网新闻信息服务许可证》，个人主体拿不到 |
| 内容红线   | 只做**赛事信息聚合**，不做综合资讯、不搬新闻稿、不做评论时政         |

> 我们做的「赛事快讯」本质是**工具型信息聚合**（帮你找比赛、提醒截止），归类在工具下是站得住的。但如果内容扩展到泛 AI 行业新闻，就会被要求新闻资质。**这是产品边界，不是过审技巧。**

### 3.3 开通微信云开发

1. 小程序后台 → `开发与服务 → 云开发` → 开通（选按量付费，初期几乎零成本）
2. 记下**环境 ID**
3. 云开发的优势：**不需要买服务器、不需要域名备案、不需要配 HTTPS 证书**，云函数可直接发订阅消息

> 这是选云开发最关键的理由：**域名备案要好几天且需要主体资质，云开发直接绕开。**

### 3.4 开发

- 下载「微信开发者工具」→ 导入项目 → 填 AppID
- 工程结构按 `cloudfunctions/` 目录组织（本地已建好 `crawlAggregator`，可直接上传部署）
- 视觉与交互 1:1 照 `design/mvp.html` 转 WXML + WXSS

### 3.5 提交审核

- 上传代码 → 后台「版本管理」→ 提交审核
- 需填：功能页面说明、测试账号（我们可游客浏览，可不填）
- 首次审核通常 1–3 天

### 3.6 发布

审核通过 → 点击「发布」→ 小程序正式可被搜索到。

## 四、⚠️ 一个必须提前解决的产品坑：小程序打不开外部网页

**这是最容易被忽略、然后在开发时卡死的问题。**

小程序**不允许**直接跳转外部网页，除了一种情况（`web-view` 组件），而 `web-view` 要求把目标域名配置成**业务域名**——需要域名备案 + 上传校验文件。**主办方的域名我们控制不了，所以那条路走不通。**

但我们的核心动作恰恰是「点进去报名」。**四条可行路径**：

| 方案            | 体验    | 说明                                                                                       |
| ------------- | ----- | ---------------------------------------------------------------------------------------- |
| ① **长按识别二维码** | ★★★★★ | 把报名链接**动态生成二维码**存入云存储，用户长按识别 → 在微信内直接打开。小程序的 `image` 组件支持长按识别                            |
| ② **复制链接**    | ★★★   | 一键复制到剪贴板 + Toast 提示「已复制，粘贴到聊天窗口即可打开」。**公众号文章链接（`mp.weixin.qq.com`）在微信内可直接打开，这条路对最多来源有效** |
| ③ 用主办方已有二维码   | ★★★★★ | 上游已提供 4/37 张裁好的报名二维码，直接用                                                                 |
| ④ 引导搜索        | ★★    | 提示「微信搜索『XXX』公众号报名」                                                                       |

**落地方案（组合使用）**：

```
详情页底部主按钮：[ 复制报名链接 ]   ← 复制 + Toast，兜底所有情况
详情页提供二维码卡片：               ← 由后端把 entryUrl 转二维码
    · 上游已有二维码 → 直接用
    · 没有 → 云函数生成，转存云存储
```

> 反过来说：**这个坑让「公众号文章链接」在我们的场景里变成优势**——公众号链接在微信内点开即读，是所有来源里体验最好的。而我们的第一大来源恰好就是公众号（7/37）。

## 五、阶段 ②：公众号绑定（你要的「想办法绑定」）

### 5.1 官方规则（已核对到官方口径）

| 问题             | 官方答案                                                     |
| -------------- | -------------------------------------------------------- |
| 公众号能关联小程序吗？    | **能。关联本身不挑公众号类型**，公众号后台 `小程序管理 → 关联小程序` 发起，填 AppID 即可    |
| 需要小程序管理员确认吗？   | **默认不需要**（2019 年起取消强制确认，可在小程序端设置「无需确认/需确认/不允许被关联」）       |
| 关联数量限制？        | 公众号可关联同主体 10 个 + 非同主体 10 个；「小程序最多被 500 个公众号关联」的限制**已取消** |
| 图文里插小程序卡片要关联吗？ | **不需要**。官方明确：「公众号文章中可直接使用小程序素材，无需关联小程序」                  |
| 自定义菜单跳小程序呢？    | **需要先关联**。未关联会出现「小程序未关联，菜单设置无效」                          |
| 未认证的公众号？       | 关联可以做，但**自定义菜单插外链受限**（未认证订阅号仅限跳公众号内部页面）；小程序卡片仍可用         |

### 5.2 三条通路，按可用性排序

| 通路                | 需要认证？  | 需要关联？     | 优先级                |
| ----------------- | ------ | --------- | ------------------ |
| **图文内嵌小程序卡片**     | ❌ 不需要  | ❌ **不需要** | **P0 —— 零门槛，立刻能用** |
| 公众号资料页展示「相关小程序」   | ❌      | ✅         | P1                 |
| 自定义菜单「找赛事 → 跳小程序」 | 未认证号受限 | ✅         | P2                 |

**结论：即使你的公众号是个人未认证订阅号，也能走通「图文推小程序卡片」这条路。** 这是最稳的绑定方式，而且恰好就是「公众号做触达」的定位——**每期推一篇赛事精选，文中挂小程序卡片，读者点开就能筛能收藏。**

### 5.3 绑定操作步骤

```
公众号后台 → 广告与服务 → 小程序管理 → 添加 → 关联小程序
  → 管理员微信扫码验证
  → 输入小程序 AppID
```

### 5.4 反向：小程序 → 公众号 / 视频号（2026-10-07 核实并已落地）

这一节回答「能不能在小程序里放一个跳转到公众号或视频号的入口」。**结论分两半：视频号能跳，公众号不能"跳"但能"关注"和"读文章"。**

#### A. 视频号 —— 可以跳，而且门槛已经放开了

| 能力 | 调用方式 | 主体要求 |
| --- | --- | --- |
| **打开视频号主页** | `wx.openChannelsUserProfile({ finderUserName })` | **无主体限制**（2023-12-20 起放开） |
| 打开单条视频 | `wx.openChannelsActivity({ finderUserName, feedId })` | 无主体要求 |
| 打开视频号活动 | `wx.openChannelsEvent({ finderUserName, eventId })` | 需同主体或关联主体 |
| 打开／预约直播 | `wx.openChannelsLive` / `wx.reserveChannelsLive` | 需同主体或关联主体 |
| 内嵌播放（不跳出小程序） | `<channel-video>` / `<channel-live>` 组件 | 2.31.1 起非个人主体可嵌非同主体 |

**只想要「点一下进我们视频号主页」，用第一行那个 API 就够了，不需要小程序和视频号同主体。** 参数 `finderUserName` 在「视频号助手」首页可以查到（形如 `sph` 开头）。

#### B. 公众号 —— 没有"跳转主页"这个能力

微信**不提供**「小程序打开公众号主页」的接口。能做的只有两件事：

| 想做的事 | 可行的方式 | 硬限制 |
| --- | --- | --- |
| **让用户在小程序里关注公众号** | `<official-account>` 关注组件 | ① 高固定 84px、最小宽 300px；② **只有扫小程序码等特定场景进入时才显示**（场景值 1047/1124/1011…），普通入口进来不显示；③ 需在小程序后台「设置 → 关注公众号」配置，且公众号与小程序**同主体或关联主体**；④ 用户已关注则不显示 |
| **让用户读某一篇公众号文章** | `wx.openOfficialAccountArticle({ url })` | ① 需基础库 **3.4.8+**；② **必须由用户点击触发**，会先弹确认框；③ 只能打开正常已发布的文章链接 |

> ⚠️ 注意：`wx.openOfficialAccountArticle` 打开**非本主体**公众号的文章，长期当作纯引流入口使用，有被判定「纯引流」处罚的先例（社区已有封禁案例）。要挂就挂自己公众号的文章。

#### C. 已经写进代码的部分

`miniprogram/config.js`（唯一开关，留空即不显示）：

```js
module.exports = {
  finderUserName: '',        // 视频号 ID，填了「我的」页就出现「视频号 → 进入主页」
  oaArticleUrl: '',          // 公众号文章链接，填了出现「公众号文章 → 阅读」
  enableOfficialAccount: false  // 公众号后台配好关注组件后改 true
};
```

「我的」页会多出一个「关注我们」分组：

- 填了 `finderUserName` → 「视频号　进入主页 ›」，点击走 `wx.openChannelsUserProfile`
- 填了 `oaArticleUrl` → 「公众号文章　阅读 ›」，点击走 `wx.openOfficialAccountArticle`（低版本微信自动降级为复制链接）
- `enableOfficialAccount` 为 true 且从扫码场景进入 → 追加微信原生的「一键关注公众号」组件

**空配置时整块不渲染**，不会出现点了没反应的死链；万一被点到，也会明确提示「还没配置」而不是静默失败。已用桩件跑过 14 项断言（配置分支、API 参数、低版本降级、场景值判断、wxml 字段与事件绑定一致性），全部通过。

#### 更正：命名不构成约束（2026-10-07 修订）

上一版这节写的是「三端名称必须一致，否则视频号认证要花 300 元」。**这个结论本身没错，但对本项目不适用——因为我们根本不需要做视频号认证。**

官方原文：**「从 2023 年 12 月 20 日起，通过 `wx.openChannelsUserProfile` 跳转到视频号主页将不再受主体限制。」** 也就是说：

| 条件 | 是否需要 |
| --- | --- |
| 视频号认证 | ❌ **不需要** |
| 小程序与视频号同主体 | ❌ **不需要** |
| 名称一致 | ❌ **不需要** |
| 花钱 | ❌ **不花** |

视频号认证（300 元/年）解锁的是**直播带货、视频号小店**这类商业变现能力；我们只要「点一下进主页」，用不上。

**所以名称按你们已经定的来，不需要为这个功能改名。**

| 平台 | 名称 | 是否影响 |
| --- | --- | --- |
| 公众号 | 沿用已定名称 | 不影响 |
| 视频号 | 沿用已定名称 | 不影响 |
| 小程序 | **赛场** | ⚠️ 见下 |

⚠️ **小程序名「赛场」有两个要提前知道的风险**：

1. **长度卡在下限**：微信规定小程序名称 **4–30 字符，1 个中文 = 2 字符**。「赛场」= 2 中文 = **4 字符，刚好压线**，合法但无任何余量。
2. **过于通用，极可能被占用**：小程序名称在**小程序平台内全局唯一**，且不得与**不同主体**的公众号重名。「赛场」这种大众词很可能已被占。**建议准备 2–3 个备选**（如「造物赛场」「未来造物赛场」「赛场情报局」），注册时按顺序试。

名字备选是**注册当场就能试**的，不影响现在任何代码。

## 十、登录方案：平台边界与三种形态（2026-10-07 实测）

网页预览版（`site/`）的登录复用 WorkBuddy 托管云服务。**它的三种登录方式都会带平台痕迹，这是托管平台的边界，不是配置问题。**

| 通道     | 用户在界面上看到什么                                         | 能否去掉平台痕迹                               |
| ------ | -------------------------------------------------- | -------------------------------------- |
| 微信网页登录 | 整页跳转 `www.workbuddy.cn/v2/as/genie-baas/oauth` 再授权 | ❌ 平台持有微信网站应用资质与 Relay，应用方拿不到 AppSecret |
| 手机验证码  | 页面是我们自己的表单；**短信签名固定为【workbuddy】**（平台下发，不可改）        | ⚠️ 页面干净，短信带平台名                         |
| 邮箱验证码  | 发件人为平台/腾讯云地址                                       | ❌                                      |

外加域名本身是 `*.app.workbuddy.host`。**结论：H5 托管版无法做到品牌干净。**

### 三种形态的取舍

| 形态                         | 登录方式                       | 品牌干净      | 代价              |
| -------------------------- | -------------------------- | --------- | --------------- |
| **A. 小程序**（最终形态）           | `wx.login` 静默登录，无任何跳转与第三方页 | ✅ 完全干净    | 需要 AppID（走认证路径） |
| **B. H5 只留手机验证码**（当前已改为这版） | 自有表单 + 平台短信                | ⚠️ 仅有短信签名 | 短信通道是否开通需实测     |
| **C. H5 不做账号，用「设备同步码」**    | 无登录                        | ✅ 完全干净    | 收藏靠短码手动搬运，非自动同步 |

### 当前网页版的处理（已实施）

1. **移除微信网页登录入口**——它是唯一会把用户整页甩到平台域名的方式，且小程序内本来就用原生 `wx.login`，H5 上保留它没有意义。
2. **保留手机验证码登录**（页面无第三方字样）。若短信通道未开通，界面会直接报错，属正常反馈。
3. **新增「设备同步码」**（选项 C 的落地）：把已收藏的赛场编码成一串短码（`ZW1` + 下标 + 校验，36 场规模下单个收藏仅 5 字符，全量 40 字符），在另一台设备粘贴即可还原。**全程不经过账号、零平台痕迹**，作为不登录时的跨设备方案。

> 编码规则：`ZW1` 前缀 + 每个收藏一位 base36 下标（宽度按赛事总数自适应）+ 一位校验位。已通过往返、篡改、截断、乱码四类测试。

### 一句话结论

**要品牌干净、登录自然，答案是小程序，不是网页。** 网页版只作功能参照稿。

## 十二、登录口径定稿：顺序「小程序先上线 → 再关联公众号 → 登录只走小程序」（2026-10-07 落实）

### 12.1 结论

| 问题        | 定稿                                             |
| --------- | ---------------------------------------------- |
| 上线顺序      | **小程序先上线**，公众号后关联。逻辑上不可倒：公众号要挂小程序卡片，得先有已发布的小程序 |
| 登录方式      | **只用小程序原生登录**（`wx.login`），公众号不参与登录链路           |
| 网页版（H5）登录 | **降级为功能参照**。它做不到品牌干净（见 §十），不投入                 |
| 公众号的作用    | **只做入口与触达**：图文挂小程序卡片、自定义菜单、资料页关联。不做授权登录        |

**为什么这条顺序能解决登录问题**：之前的卡点是「H5 上无论哪种登录都带平台痕迹」——微信网页登录必须跳平台中转页，短信签名固定是平台名。而小程序原生登录走的是**微信自己的身份体系**：`wx.login` 拿到的是微信发的临时凭证，由我们自己的云函数在服务端换成 openid，全程在 `wx` 命名空间内完成，**页面不跳转、域名是我们自己的、界面上不会出现任何第三方品牌**。这是换载体换来的干净，不是配置技巧。

### 12.2 完整链路（已实现）

```
用户在「我的」点「微信一键登录」
        │
        ├─ 1. wx.login()              微信签发一个 5 分钟有效的临时 code
        │                               （静默，无弹窗、无跳转）
        │
        ├─ 2. wx.cloud.callFunction   小程序 → 云函数 login
        │      ({ name: 'login' })      ★ 前端不传 code、不传任何身份信息
        │
        ├─ 3. 云函数 cloud.getWXContext().OPENID
        │                              云端从调用上下文里直接拿到调用者身份
        │                              （AppSecret 只存在微信与云端，前端不接触）
        │
        ├─ 4. 写 users 集合             首次登录建档，非首次更新 lastLoginAt
        │                              返回账号短号 ZW-XXXX-XXXX（openid 的不可逆派生）
        │
        └─ 5. 收藏并集合并             本机独有的上传到 favorites，云端独有的补回本机
                                       （规则：只增不删，本机那份永远是事实来源）
```

**关键设计取舍：前端不存 openid、不存 AppSecret。** 前端只存一个账号短号 `ZW-AB12-CD34` 用于界面展示，它由 `md5('zw:' + openid)` 派生——同一个用户永远得到同一个短号，但反推不出 openid。收藏读写则完全交给云开发权限体系：`favorites` 集合权限设为「仅创建者可读写」，客户端的查询天然被限定在自己的数据上，连条件都不用拼。

### 12.3 三层收藏兜底（任何一层挂了都不影响使用）

| 层 | 机制                       | 什么时候用                            |
| - | ------------------------ | -------------------------------- |
| 1 | 本机缓存 `wx.setStorageSync` | **永远可用**，是事实来源。登录、断网、云函数挂了都不影响   |
| 2 | 云端 `favorites` 集合        | 登录后开启，收藏跟账号走，换设备自动取回             |
| 3 | 设备同步码（`utils/sync.js`）   | 未登录 / 没开通云 / 无网络时的跨设备手段，一串短码手动搬运 |

> 设计原则是**降级不残缺**：`config.js` 里 `CLOUD_ENABLED: false` 时（即现在，还没拿到 AppID），登录按钮会明确提示「云开发还没开通」，但浏览、搜索、收藏、设备同步码全部照常工作——不会白屏，也不会报错。
