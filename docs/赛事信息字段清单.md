# 赛事信息字段清单（主要信息不会丢）

> 状态：v1.0 · 2026-10-07
> 用途：① 定义「一场赛事的完整信息」到底包含什么；② 作为后台审核界面的字段依据；③ 作为抓取/映射的验收标准。
> 数据来源：实测 HackerTrip 公开 feed 37 条赛事（`/api/hackathons`，35 个字段），逐字段核对承接情况。

---

## 一、核心结论：上游 35 个字段，已全部承接，无遗漏

映射器 `cloudfunctions/crawlAggregator/mappers/hackertrip.js` 的实测验收结果：

| 指标 | 结果 |
|---|---|
| 上游字段总数 | 35 |
| 未承接字段 | **0** |
| 正文无损（简介/详细描述） | **36/36** |
| 奖金信息无损 | **36/36** |

**三个必须说明的点：**

1. **上游没有 `tags` 字段** → 赛事标签由我们自行推导（依据主题 / 标题 / 赛道）。
2. **上游 `brief` / `infoCards` / `logo` 三个字段 37 条全为空** → 无内容可承接，需另找来源。
3. **数据层不做有损截断** —— 上游给什么就完整存什么，短版本另存 `xxxShort` 字段供列表展示。**截断发生在展示层，不发生在数据层。**

## 三、标签推导规则（上游无此字段）

两轮策略，**准确率优先于召回率**：

1. **第一轮**只扫高置信字段（主题 / 标题 / 赛道），并跳过泛化标签；
2. 第一轮无命中时，**才**用简介兜底，此时允许泛化标签。

> 简介里「交互游戏」「科普」「设计」这类词极易误命中，**绝不作为第一轮来源**。
> 修正前 Mathathon 被误判为「游戏开发」（因简介提到"交互游戏"），修正后为「大模型 / 教育 / 数学」。

## 四、发布门槛规则（写进后台校验）

### 拒绝发布（硬性）

- 缺 `title` 或 `slug`
- 缺 `startDate` / `endDate`
- 缺 `entryUrl`（用户点进去无处可去）
- `verifyState = 'conflict'`（与主办方官方页面冲突且未解决）

### 标黄待办（可先存稿，不发布）

- 缺 `regDeadline` → 提醒功能失效，**必须补**
- 缺 `authoritativeUrl` → 6 项关键信息无法核验
- 缺 `posterRemote` → 用模板兜底，允许发布
- 缺 `prizePool` → 用户最关心的信息之一，尽量补

### 一期数据现状（37 条实测）

| 待办项 | 条数 |
|---|---|
| 无海报，需模板兜底 | 14 |
| 入口为托管平台，需回溯主办方自有域名 | 13 |
| 报名走托管表单，截止以官方公告为准 | 8 |
| 报名截止缺失，需补全 | 7 |

## 五、上游没给、我们必须自己补的信息

| 信息 | 为什么重要 | 怎么补 |
|---|---|---|
| **参赛资格** `eligibility` | 用户判断「我能不能参加」的第一依据 | 从主办方页面抓取；或后台人工录入 |
| **提交要求** `submitReq` | 决定要不要组队参赛 | 同上 |
| **技术栈** `techStack` | 影响「技术栈匹配推荐」功能 | 从 `tracks` 文本人工拆分，或从原页抓取 |
| **主办方官网** `authoritativeUrl` | 13/37 缺失，导致无法核验 | `verifyAgainstSource` 尝试回溯；失败则人工补 |
| **赛事方 Logo** | 详情页品牌呈现 | 上游全空，从主办方页面抓 |
| **报名二维码** | 小程序内体验最优 | 上游只给 4/37，其余从海报里裁（**HackerTrip 的做法，已采纳**） |
